## 四、执行链路（本次最严重项）

1. **交易时段零扫描 → 已批准结论全部落空**。激进版 09-28 `log` 时点为 `07:23:38 / 07:26:46–07:28:33 / 07:33:41 / 22:56:45`，**09:30–15:00 之间无任何扫描或访问**。源码核验：`execute_approved()`（`server.py:1084`）首行即以 `in_trading_hours()` 拦截（1092），补成交入口 `maybe_catchup()`（1171）同样以 `in_trading_hours()` 为前置（1179），仅在 `do_GET`（1508）被调用 → **"盘前批准 → 服务端在交易时段自动成交"这一设计，在盘中无人访问服务端时必然落空**。结果：茅台、浪潮两只 `approved` 全天 0 成交。
2. **`reviewTTLHours=24` 对 `approved` 同样生效 → 跨休市窗口必然作废已决策标的**。证据链：09-25 21:44 宁德时代/比亚迪各获批 BUY（信心 6）→ 中秋休市 9/25–9/27 → 09-28 **07:23:38**（尚未开盘）`评审队列 TTL 作废 2 只：宁德时代、比亚迪`，`expiredReviews` 记为 `state:"approved", waitedH:57.7`。**因果：批准时刻距下一开盘 >24h → 决策被清除，而非被执行。** 推论：09-28 07:28:29 获批的浪潮信息，TTL 到期 = 09-29 07:28:29（**仍早于 09-29 开盘**）→ 若 09-29 开盘前扫描，将**再次被 TTL 作废，预计继续 0 成交**（可检验预测）。
3. **`reviewMaxAgeMin` 仍缺失**（稳健版有 240）。激进版队列虽已因 TTL 而清空，但代价是"**approved 也被清**"，与稳健版"只清 `waiting`"语义不同 → 属**用错机制换来的清空**。

## 五、经验蒸馏

### 5.1 激进策略独有

- **[2026-09-28] 盘后/盘前批准 + 服务端交易时段成交的"解耦设计"，在盘中无人访问服务端时必然全部落空。** 证据：激进版 09-28 两只 `approved`（茅台 07:28:32、浪潮 07:28:29）**全天 0 成交**；`log` 显示 **09:30–15:00 零扫描**，`execute_approved()` 与 `maybe_catchup()` 均以 `in_trading_hours()` 为前置且后者挂在 `do_GET` → 无请求即无成交。**命中 1 次（激进独有实证；稳健版因长期满仓、无待执行指令而未受损）**
- **[2026-09-28] `reviewTTLHours=24` 对 `approved` 生效，使"跨休市/跨周末的批准"必然被作废而非被执行。** 证据：宁德时代、比亚迪 09-25 21:44 获批（信心 6）→ 09-28 07:23:38 作废，`waitedH=57.7 > 24`。**命中 2 只（同批）**

### 5.2 两版通用

- **[2026-09-28] 宏观总量级快讯不可作个股买入依据（累计第 7 例）。** 证据：09-28 07:21「国庆长假即将开启 文旅消费市场火热」→ 茅台 score 2 / 五粮液 score 2 入队；事后茅台 +0.56%（**纯运气且 0 手**）、五粮液 -1.09%。同型失效累计 **7 例、跨两版独立复现**。
- **[2026-09-28] 高价股在"100 股整手 × 比例预算"下系统性不可买（第 3 个独立队列实例）。** 证据：茅台 1237.00×100 = 123,700 元 = 总资产 123.7% > `maxPosPct=45%`（45,000）> 35% 预算 → **0 手**；评审本身已明确写出"数学必然 0 手，不可执行"**却仍占用队列名额**。激进版阈值 = 450 元/股（45,000÷100），稳健版 = 300 元/股。
- **[2026-09-28] "已批准但未成交"是比"未批准"更坏的状态**（操作性结论）：它同时占用队列名额、消耗 TTL 时钟、产生"已决策"的错觉，且会被 TTL 以"超时未评审"的名义清除（`why="TTL 超时未评审"` 对实际是 `approved` 的条目措辞失真）。

## 六、参数建议

**不建议调整任何交易类参数**（`minScore` / `buySigFloor` / `minAgree` / `buyPct` / `maxPosPct` / `cooldownMin` / `useVal` / `stopLossPct`）。
依据：连续 **9 个交易日 0 成交**，`trades=[]`、`fees=0`、`realized=0` → 上述参数**一个都没有成交样本**；`buySigFloor=-2` 的新样本（浪潮 -4.08%）为**证据削弱**而非收窄证据（此前 09-18 正收益已在 4 日内回吐 55%），**既不足以支持放宽也不足以支持回收**。

**流程类建议（按优先级，均为"待用户确认"，本轮未生效、未修改任何配置）**：

1. **让"批准"与"成交"共用同一个时间窗**：把本自动化的触发时点（或任何一次访问）放到 **09:30–15:00**（如 10:00 / 14:00），使 `maybe_catchup()` 有机会落地；或把 `approved` 的成交从"需 `in_trading_hours()`"改为"下一可交易时段自动补做"。依据：09-28 两只 `approved` 全天 0 成交，交易时段零扫描。
2. **`TTL` 只应作用于 `waiting`，`approved` 应"冻结"而非"作废"**（或把 `reviewTTLHours` 的起算改为"下一交易日开盘后"）。依据：宁德时代/比亚迪 09-25 21:44 获批 → 09-28 07:23:38 作废（57.7h）。
